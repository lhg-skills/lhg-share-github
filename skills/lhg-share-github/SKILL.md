# lhg-share-github：把 GitHub 项目合规放到 Gitee 分享

## 解决的问题

用户给一个别人或自己在 GitHub 上的公开项目，想让国内用户不用 GitHub、不用 VPN 就能拿到并使用。Skill 的默认解法不是建 GitHub 组织，也不是把代码复制成一个新仓冒充原创，而是：核实许可，合规导入到 Gitee 组织，对外只发 Gitee 链接。

## 默认值（用户本轮没有另说时就用这些，不要重新问一遍）

- 分享渠道：Gitee，不用 GitHub 组织。GitHub 组织路线（例如曾提过的 lls-github-star）已经作废，不要复活它。
- 归属：Gitee 组织，默认 `lls-find-hub`。不要默认沿用 GitHub 组织名，GitHub 和 Gitee 的同名组织不一定都存在。
- 仓名：默认用上游仓名，不要另起花名，方便受众一眼认出。
- 仓属性：默认开源（所有人可见）。私有仓受众打不开，达不到分享目的。
- 同步：默认手动同步，不要默认开自动同步。自动同步才需要 GitHub 令牌。
- 改动：默认不改上游代码，不改 README，不删 LICENSE。

## 触发后先问清的唯一缺口

只问会改变目的地的事，其他先按默认值推进：

- Gitee 组织名：用户没有给过、也没有默认可用时，问组织名。已经给过 `lls-find-hub` 的对话里不要再问。
- 组织不存在时是否新建：没有用户明确说“先创建”之前，停下问一句，不要擅自建组织，也不要擅自改用个人空间。
- 仓名或开源属性：用户本轮另有指定时才改，否则用默认值。

不要在聊天里向用户索要 Gitee 或 GitHub 的密码、令牌、验证码。登录走浏览器正常流程和安全入口。

## 第一步：核实上游，核实完再动手

用 GitHub API 或仓库页核实并记下来，核实不到的不要编：

- 上游地址、所有者、默认分支、最新提交 SHA、提交时间、树规模（文件数加目录数要分开说，不要把树项数说成文件数）。
- 代码许可全文与版权人，例如 MIT 加 Copyright 人。许可不明的仓，先停下说明，不要默认当成可自由转载。
- 拆开许可，不要混成一句话：代码许可、数据集许可、古籍或引用文本许可可能各不相同。例如数据集可能是 CC BY 4.0，要求保留来源标注；引用的他人原话可能是 CC BY-NC-SA 4.0，非商用。哪一部分能商用、哪一部分不能，必须分开写。
- 数据集如果在 Releases 里，不在 git 仓里，就要写明：导入 git 仓不等于导入数据集，不要在介绍里写内含数据集。
- 上游有没有 SKILL.md：如果没有，这不是一个 Skill 包，不要把它当 Skill 直接提交到 SkillHub，见文末 SkillHub 一节。

## 第二步：登录与组织

- 用浏览器任务打开 Gitee，让用户本人完成登录。登录前组织页显示 404 不能当作组织不存在的证据，未登录无权查看也会 404。
- 登录后先确认三件事：组织是否存在、当前登录账号是不是该组织成员、有没有建仓权限。三者缺一就停下回报，不要绕过去。
- 组织不存在时，只有用户说过“先创建”才新建，标识和名称都用用户给的组织名，简介用中性描述，例如“开源项目合规镜像收藏”，不要写原创声明。
- 不要用个人空间代替组织，不要用另一个同名或近似名的组织代替，例如用户更正过的名字以后者为准，前一个作废。

## 第三步：导入

按 Gitee 组织页的正规流程走，不要用第三方代理镜像站当正式分享渠道：

- 进入组织页，新建仓库，选开源。
- 通过新建页的导入入口（“从 URL 导入”或“导入已有仓库”）填入上游 GitHub 地址，页面地址和 `.git` 地址都可以。
- 公开仓直接创建即可，不需要先绑定 GitHub 账号。私有仓才需要登录有权限的 GitHub 账号授权，授权后再导入。
- 导入完成后立即改仓库描述，照抄下面的模板，只替换中括号部分，不要加原创、自研、首发这类表述：

```
原作者 [上游所有者] 的 [项目一句话描述]（[代码许可]），本仓仅作国内分享中转，不改原代码、不声称原创；数据集 [数据集许可与标注要求]，[引用文本的非商用等限制]。上游：[上游 GitHub 地址]
```

- 如果某部分许可不存在，就删掉对应分句，不要留空括号，也不要编一个许可出来。

## 第四步：验收，验收完才发链接

逐项核对，任何一项对不上就先修再交付，不要把浏览器任务的回传原样转发：

- 仓库能公开打开，并标注为公开仓库。
- 默认分支与上游一致，通常是 main。
- 根目录有 LICENSE，数据集许可文件（例如 DATASET-LICENSE）如果上游有，也要在。
- 最新提交 SHA 与导入时上游 HEAD 一致，记下短 SHA 和提交标题。
- 树规模分开报：文件多少个、目录多少个、合计多少项。
- 上游代码没有被改动，描述里没有原创表述。
- 最后用受众视角验证一次：给出的克隆命令能拉下来。

验收通过后交付给用户的内容只有四样：Gitee 仓库地址、克隆命令、最新提交 SHA、验收数字（公开、分支、许可文件、树规模）。不要同时发 GitHub 组织链接当作分享链接。

## 停止条件

出现下面任何一种就停下，先说明卡点和能马上做的窄方案，不要硬走下去：

- 上游许可不明，或者许可明确禁止再分发。
- Gitee 登录没有完成，或者登录账号不是目标组织成员、没有建仓权限。
- 目标组织不存在且用户没有说先创建。
- 导入后 SHA、许可文件或公开属性对不上。
- 用户要求把导入仓说成原创、删 LICENSE、删署名，或者把非商用部分说成可商用。拒绝这一项，继续做合规的部分。

## SkillHub 的位置（不要和 Gitee 导入混成一步）

- Gitee 导入解决的是“国内能下载代码”，SkillHub 解决的是“作为 Skill 被发现和安装”，两者不是同一交付。
- 如果上游没有 SKILL.md，直接提交该仓到要求 SKILL.md 的 SkillHub 会被校验跳过。这时只有两条合规出路：目标平台接受仓库收录就直接提交 Gitee 或 GitHub 仓链接加说明；目标平台只收 Skill 就另建一个只放 SKILL.md 的包装仓，写调用步骤和署名许可边界，不复制上游代码和数据集，再提交包装仓。
- 对外分享时，Skill 用户发 SkillHub 链接，代码用户发 Gitee 链接，不要把两个链接的作用说反。

## 已验证的案例（当作回归样本，不要当作通用答案）

- 案例：上游 `Renhuai123/ziwei-doushu`，紫微斗数开源排盘引擎，代码 MIT（Copyright (c) 2026 紫微研究），数据集 CC BY 4.0（作者标注王多鱼AI，需保留来源标注），倪师原话 CC BY-NC-SA 4.0 非商用，数据集在 Releases 不在 git 仓。
- 结果：Gitee 组织 `lls-find-hub` 为新建，仓 `https://gitee.com/lls-find-hub/ziwei-doushu`，开源，最新提交 `ff9a1470ebe652e57b9d690f5d01db9a04f47aae`，树 149 项（文件 122 个，目录 27 个），描述已按模板改好。
- 教训：组织页未登录的 404 不能当作不存在；GitHub 组织名不能默认套到 Gitee；树项数不能说成文件数。
